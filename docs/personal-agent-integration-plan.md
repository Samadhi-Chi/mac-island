## 1. 产品目标和首版范围

让用户在 Island 看清哪些 Agent 有任务、哪些任务需要处理，并返回原来的应用或已验证的目标任务。首版实现：

- 原生 Agent 名称与原生任务标题分别展示；不重新命名，不用目录、第一条消息或摘要冒充标题。
- 显示有证据支持的任务状态、原生更新时间，以及 Island 最近核实信息的时间。
- 明确观察范围：当前可见会话、当前可见活动列表，或经验证的任务数据源。
- 显式打开来源应用；只有取得可信目标身份并完成真实导航验收后，才提供打开具体任务。
- 独立的启用、暂停、权限状态和重连入口；停靠与悬浮共用相同语义。

首版沿用本机、静音和观察模式。发送消息、执行审批、停止或重启 Agent、创建任务、恢复云端运行均不在本轮实现范围。重连仅恢复 Island 自己的观察器。

本轮优先本地只读来源。远程 Connector、MCP 主动上报或企业事件导出是候选后续方案，不能暗中变成首版的网络服务、账号登录或云端部署。

## 3. 支持等级与准入规则

每个客户端、每个版本独立记录支持等级。设置中的“应用可见”与“任务观察可用”分开显示。

| 等级 | 可交付能力 | 准入条件 |
| --- | --- | --- |
| 应用入口 | 识别应用、显式打开应用 | bundle 身份与打开结果核实；没有任务状态承诺 |
| 当前界面观察（实验性） | 展示当前可读的会话/活动卡片 | 原生标题/身份范围可靠，状态不足时明确显示无法确认；切换界面不会误合并任务 |
| 持续任务观察 | 持续追踪已识别任务及状态变化 | 可信稳定身份、明确状态、后台/最小化/多窗口及重连验收通过 |
| 具体任务导航 | 打开指定原生任务 | 独立导航证据与真实目标确认；macOS 接受 URL 仅报告请求已发送 |

没有稳定原生任务 ID 的卡片只在内存里按当前观察范围展示，不能用标题哈希、列表位置、窗口 ID 或随机值冒充原生 ID。此类卡片不进入最近记录，不提供复制原生 ID或具体任务恢复。

无法达到持续观察等级时，可以交付明确标注覆盖范围的实验版。Dot 数据源不可用时保留待办，不能以显示应用图标或显示普通 Codex 会话代替 Dot 接入验收。

## 4. 信息模型与状态规则

采用三层关系：Agent、任务、执行会话。一个 Agent 可以同时处理多个任务；一个任务可委派给 Codex。列表以可验证的任务/执行会话为核心，Agent 名称作为归属信息。

新增 Personal Agent 观察模型，至少包含客户端、可选账号范围/原生 Agent ID/原生任务 ID、原生标题、状态证据、来源、观察范围、最近成功观察时间、可选原生活动时间和导航能力。项目路径、模型、开始时间不是必填字段；源端未提供就不显示。

- 身份按客户端、账号范围、Agent 和原生任务区分；两个同名任务不得合并。
- Dot 委派的 Codex 会话沿用现有原生 Codex 身份。只有来源提供可信关联时，才标注 Dot 归属；不通过标题、目录或时间接近猜测关系，也不重复创建同一执行会话。
- 任务状态和观察健康分开。任务可以持续运行但暂时没有新进度；观察器也可能断开而任务仍在云端运行。
- 用户改名后，较旧的异步读取不能覆盖新名称。缺失标题沿用“标题暂不可用”，不生成替代标题。
- “最近核实”与“最后活动”分开，不能在每次轮询时刷新任务活动时间，把旧任务永久留在当前列表。
- 日期、时区和相对时间无法可靠解析时显示原生时间或缺失，不回退为 1970 年，不把计划中的未来任务当作当前运行任务。

| 展示状态 | 必要证据 |
| --- | --- |
| 正在运行 | 当前任务的明确运行状态或经过认证的生命周期事件 |
| 等待你处理 | 当前任务的明确待审批/待输入记录；Approvals 按钮存在本身不构成证据 |
| 已完成 | 当前任务的明确完成状态或完成事件 |
| 失败 | 当前任务的明确失败状态；标题或回复提到别的系统失败不能触发 |
| 已取消 | 当前任务的明确取消状态；应用退出不是任务取消 |
| 已计划 | 来源明确给出的调度状态；与运行任务区分 |
| 暂无法确认 | 信息缺失、过期、权限撤销或界面不可读；保留最近核实时间 |

状态映射必须逐客户端认证，不按回复文字里出现“完成”“失败”等词汇猜测。无可靠运行状态的历史 Activity 只展示已观察的活动记录，不冒充当前运行任务。

## 5. 接入架构与本地观察策略

新增独立的 Personal Agent 观察模块，归一化后接入现有 `SessionMonitor`、状态与展示路径；不改写整个 Codex 运行时。建议模块职责如下，名称可随实现细化：

- `PersonalAgentObservation`：内存中的原生信息、状态证据、身份与覆盖范围。
- `PersonalAgentAdapter`：每个客户端独立解析与能力判断。
- `PersonalAgentMonitor`：管理生命周期、取消、健康及代次。
- `AccessibilitySnapshotReader`：只读、限定目标应用与允许的 UI 区域，提供有界读取。
- `PersonalAgentCapability`：版本、身份、状态、后台覆盖和导航能力分别认证。

读取优先级是已支持且可验证的本机结构化接口，其次是应用提供的可访问性属性；每项都必须有版本与契约证据。没有可信接口时降低支持等级。

可访问性观察限定用户明确启用的应用，优先标题、状态、Activity/Approvals 等必要区域。观察层不自动点击、切换会话、滚动历史或抢占焦点。读取当前界面不代表自动获取全部历史。

启用项与 macOS 辅助功能授权分开：开启观察不会自动获取权限，不反复弹窗；权限不足时说明原因并提供系统授权入口。账号登录、Grok/Muse Connector 授权不属于这个权限流程。

优先使用可用的变化通知，配合低频校验；通知是否有效必须实测。读取有超时、深度、节点数和并发上限，工作放在独立执行上下文，不能阻塞主界面。复用 `EnergyGovernor`：锁屏/休眠停止读取，唤醒后重新核实；安静不等于故障。

客户端升级或界面结构不匹配时关闭该解析路径并显示无法确认。其他客户端继续工作，不进入无限重试。暂停、退出和卸载观察项只回收 Island 自己的资源，不终止外部 Agent。

## 7. 列表与设置设计

沿用“当前会话”主入口与“最近记录”次级入口，不增加 Grok/Muse/Dot 各自的重复 tab。

2026-10-08 根据用户要求，以 Bot 为单位展示：每个当前可识别的 Bot 上下文一张卡，原生 Bot 名称为标题、客户端为副标题，原生活动默认折叠在卡片内。活动保留顺序和重复记录，但不增加会话数量。没有名称时明确显示缺失，不用活动标签补造 Bot 名称；不同窗口/面板不按名称合并，也不声称已发现全量 Bot。若以后取得稳定原生 Bot/任务身份，可在卡片内增加经过认证的任务导航。

运行状态、最后核实时间与明确的打开按钮保留；项目和模型只在来源提供时显示。历史活动的组合标签不拆成独立任务标题、状态或时间。切换 Muse 侧栏时已识别的 Bot 保留，旧活动清空。弱身份的展开状态只属于当前快照。

需用户处理的任务优先，其次明确运行的任务；已计划活动不占用“正在运行”计数。未知状态和历史活动不进入运行数量。未能完整观察所有后台任务时，数量明确限定为“已观察”，不冒充账号全部任务。

“最近记录”仅接收满足稳定身份和保留契约的数据。Personal Agent 可能没有项目目录，不能给它伪造目录以通过现有模型。实现前检查 `MacIslandSessionSnapshot`、导航模型和 `RecentSessionIndex` 的必填目录约束；仅在新模型/兼容迁移验证后接入，否则首版保持内存展示。

最近索引维持 7 天/200 条等既有保留规则，清空只影响 Island。原生名称留在内存，不进入最近索引、路由缓存或诊断；弱身份卡片不保存。

设置中每款显示“关闭”“需要权限”“仅观察当前界面”“持续观察可用”或“暂不可用”，并提供启用/暂停、重新检查和打开来源应用。复用已有中性安装/启用标记、系统强调色和警告语义，不把客户端品牌色当作状态色。

打开操作独立于观察层，只由显式点击或已绑定快捷键触发。导航结果继续区分“应用已打开”“打开请求已发送”“目标已确认”“不可用/失败”；不因为 scheme 存在就宣称返回了目标任务。

## 8. 自动化与真实验收

自动化使用手写合成 UI 结构和模拟数据源，不保存用户真实 UI 树、邮件、提示词或回复。针对实际风险覆盖：

- 两个同名任务、同一 Agent 多任务、多账号和不同客户端；Dot/Codex 委派关联的重复、缺失与过期。
- 原生改名、缺失标题、异步旧结果、时间缺失/未来时间/时区，历史卡片与当前任务分离。
- 明确状态与内容文字分开：处理“示例构建失败”的成功任务不能被误判失败。
- 权限拒绝/撤销、窗口关闭、应用退出/重启、界面结构变化、有界读取和取消；异常不造成重试风暴。
- 最近索引的身份/容量/清空/兼容迁移与内容字段排除；弱身份不得落盘。
- 停靠/悬浮的共用列表、键盘选择、导航反馈和设置状态；不自动展开、不抢焦点。
- Codex/Cursor/Claude/OpenCode/Hermes/DSH 的已有观察、标题、重连和导航回归。

受影响产品套件加入 `scripts/test.sh`。按用户 2026-10-07 最新指示，开发完成后统一运行一次完整门禁；若失败，只修复并复查受影响部分，不在开发期间反复跑完整测试。PR 与合并后 main 的必要 CI 门禁仍保留。纯计划文档检查链接、路径、差异和表述，不用构建成功替代计划审查。

每款真实验收至少包括：前台、后台、最小化、切换会话、多窗口、明确运行/待处理/完成/失败/取消、无任务、应用退出、断网后恢复、锁屏/睡眠唤醒和版本变化。仅能验证的状态才列为支持。最小化不可读时记录该限制，不自动点击应用补读。

开始真实运行、审批或恢复测试前，须使用专门测试任务和已有明确授权；只读调查不自行发消息或创建测试任务。Dot 工具限制无法解除时记录未运行，不伪造真实验收。

停靠/悬浮、浅深色、键盘、多屏及两个设置展示路径分别核对。持续观察等级需有至少一个完整工作时段的运行记录，并继续做覆盖睡眠/唤醒的 24 小时观察；无授权任务的状态保持未验证，不靠空闲运行替代状态验收。

性能记录同环境下观察关闭/开启的 CPU、内存、唤醒与主界面响应，使用已有能耗策略验证静默和锁屏降频。PA-02 建立对照，PA-07/08 给出实际结果与阈值依据，不凭没有测量的固定百分比宣称低功耗。

## 10. 时间估算、停止条件与最终完成定义

按单条主要开发线估算：PA-01 约 1–2 个工作日；观察基础约 2–3 日；Muse/Grok 各约 1–2 日；列表/设置约 1–2 日；稳定性与真实验收约 3–5 日。部分 UI/验收工作与客户端适配同步，首个实验适配目标为 5–8 个工作日；Muse/Grok 稳定交付约 2–3 周。

Dot 在来源可用时另估 2–4 个工作日实现与验证；三款均有可信数据源时总周期约 3–4 周。这是工作量估算，不是接口可用性或完成日期承诺。PA-01 结束后依据实测证据更新估算。

以下情况停止该客户端的升级交付，保留准确降级：原生身份不稳定、状态只能靠正文猜测、必须自动操作界面才能持续读取、版本变化后无法可靠识别、或者需要未经确认的新远程系统。持续观察不成立时，继续交付有边界的应用入口/当前界面观察。

本轮某客户端完成的定义是：支持等级和字段范围明确；原生标题一致；状态有证据且过期不误报；观察范围诚实；导航结果可解释；隐私和能耗检查通过；停靠/悬浮与既有客户端无回归；共享门禁、PR/main 检查和实际支持范围内的真实验收通过；用户可暂停并可回滚。

交付包包含各客户端版本/能力矩阵、关联 Issue/PR、自动化结果、真实验收与未运行列表、用户启用说明和回滚方式。不能用“三个图标出现了”作为三款接入完成的标准。
