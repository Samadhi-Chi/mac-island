# Personal Agent 当前界面观察

2026-10-10；来源能力跟踪 [#29](https://github.com/Samadhi-Chi/mac-island-private-archive/issues/29)，Bot 会话卡跟踪 [#31](https://github.com/Samadhi-Chi/mac-island-private-archive/issues/31)，Muse 6.0 与来源状态修复跟踪 [#36](https://github.com/Samadhi-Chi/mac-island-private-archive/issues/36)。当前为实验性界面观察，持续任务状态和 Dot 独立来源仍是开放工作。

## 支持范围

| 来源 | 版本契约 | 能展示什么 | 不能承诺什么 |
| --- | --- | --- | --- |
| Muse | 4.1；`com.meta.endo` | 侧栏身份区的原生 Bot 名称；用户已打开 Activity 时，完整组合活动标签收在该 Bot 卡片内 | 稳定 Bot/任务 ID、独立任务标题/更新时间、运行或待审批状态、所有后台 Bot/任务 |
| Muse | 6.0；`com.meta.endo` | 已核实聊天布局中两个镜像头像入口的原生 Bot 名称，归为一张当前 Bot 卡 | 本轮不读取新版 Activity；不把 Side chats 的标题当 Bot 名称，也不确认后台任务或执行状态 |
| Grok Bot | 0.68.1；`com.anysphere.sand` | 当前会话详情入口提供的 Bot 原生名称 | Bot 名称不是任务标题；不能确定当前任务 ID、运行状态或所有后台任务 |
| Dot | 当前应用身份 `com.openai.codex` | 用户显式打开 Dot 所在应用 | 未取得 Dot 独立任务源；普通 Codex 工作不作为 Dot 任务 |

读取失败、界面不匹配和超时都清除本轮来源条目。其他客户端仍可继续。未核实版本停止该客户端的解析并显示版本未核实；4.1 与 6.0 使用各自的契约，不能互相回退或自动认证未知版本。每次刷新从来源安装包重新读取版本，避免 Bundle 缓存让原地更新后的应用继续使用旧契约。

已启用但没有已核实 Bot 的来源仍在当前列表显示状态卡，说明缺少权限、观察暂停、应用未运行、版本不支持或当前页面不可读的原因，并提供“打开应用”。状态卡没有 Bot 身份、核实时间或会话 ID，不增加当前会话/运行数量，不进入最近记录。即使没有编程会话，停靠和悬浮的展开列表仍能显示这些来源状态。

Activity 是历史活动，不能算作正在运行，也不从标签中的“完成/失败”词语推断执行状态。来源未提供独立时间，所以不把 Island 的核实时间冒充活动时间。“当前会话”按会话卡计数：一个 Muse Bot 的七条活动只增加一张卡；收起状态的运行计数继续只计算可靠的编程会话。

卡片以原生 Bot 名称为标题，客户端为副标题；名称缺失时显示“Bot 名称暂不可用”，不从活动或对话内容补造。默认只显示来源顺序中的第一条活动预览与活动数量，点击展开全部已读取的标签，保留原顺序和重复记录。切换出 Activity 后清除旧活动，已识别的 Bot 仍显示一张卡。新观察快照重新收起详情，避免将弱身份的展开状态延续到另一个 Bot。

卡片和集成设置复用 [Muse/Grok Bot 像素标识](design/mac-island-client-glyphs.md)：蓝色 M 与灰色斜切头像仅区分客户端。卡片悬停时播放轻微动效，离开恢复静止；设置图标始终静止。动效遵守减少动态效果和 EnergyGovernor，不把界面可读或悬停解释为执行中。

本机研究还使用当前应用内置 CLI 离线生成的 app-server JSON Schema：`ThreadSourceKind` 包含 cli/vscode/exec/appServer/subAgent 等，没有已验证的 Dot 主任务方法；`dotCodexFolder` 只是项目 `.codex/` 目录配置。可扩展的 custom source 不构成 Dot 委派契约。没有启动另一个服务器、读取凭据、查询 Dot UI 或发送消息。这项结论只描述本次取得的协议证据。

## 使用

1. 在 Island 设置的“集成 → Personal Agent”启用 Muse 或 Grok Bot，默认都关闭。
2. 若显示需要权限，点击“授权辅助功能”，在 macOS 系统设置中允许当前 Mac Island 副本，返回点击“重新检查”。没有权限时不会反复弹窗。
3. 来源应用保持运行并让当前 Bot 的聊天或状态页面可见；Muse 4.1 在原应用手动打开 Activity 才读取活动，6.0 本轮仅读取 Bot 名称。Island 不会代点 Activity、切换会话、滚动或发送消息。
4. 展开 Island 的“当前会话”，查看“Personal Agent · Bot 会话”；点击卡片内的活动数量展开/收起。停靠和悬浮使用同一列表与键盘规则。上下方向键选择，Enter 与“打开应用”仅打开来源应用；不声称定位了具体 Bot 或任务。
5. 可分别暂停或关闭观察。“重新检查”只更新 Island 读取；不重启客户端、不安装插件或修改来源账号。

没有稳定原生 Bot/任务 ID 的观察只属于当前内存快照。同名但不同窗口/面板的 Bot 保持分开，不能凭名称证明它们是同一个 Bot；仅已识别的当前上下文可显示，不代表全部 Bot。界面切换后旧快照失效；不进入最近记录，不提供复制 ID 或恢复任务。

## 生命周期和隐私

读取器只接受上述 bundle 与版本。读属性放在独立 actor：每个 AX 消息超时 50ms、一次读取预算 2 秒、最多 3 窗口/400 节点/24 层、单个子列表最多 80 节点、标签上限 1024 字符。超过预算丢弃该来源的部分结果，不展示被截断信息冒充完整原生标签。对话和输入子树在值与后代读取前剪枝；普通静态文本不读取，仅允许必要标题控件内的文本，以及 Muse avatar / Edit avatar and name / 四个侧栏标签之间最多两个身份文本叶节点。原生头部中编辑按钮和名称分别有一层独立容器：编辑容器必须只有一个已知名称控件，名称容器必须只有一到两个直接静态文本，先核对全部叶节点角色再读取值；不接受更深容器、输入控件或额外文本。兼容相同头部的平铺组合标签或两个相邻名称/Connected 文本；只移除已核实的连接标记，不把它作为运行状态。未知标记不补造名称。

Muse 6.0 完全不读取静态文本或标题值。只有直接导航容器同时提供原生 Chat 链接、Search 按钮和 Settings 菜单，且同一根容器中固定消息入口后紧邻两个同名、无后代的头像按钮，才认可一个当前 Bot 上下文。消息入口只保留固定结构标签，不读取其后代；两个头像必须一致，缺失、非相邻或嵌套普通文本都不认可。头像中的原生“needs approval”装饰可去除，但不推断审批/运行状态；默认 Agent avatar 标签不当作名称。这个契约只验证英文控件布局；其他布局继续显示来源不可读状态。

可用 AX 通知与来源应用生命周期通知触发合并更新，最多每秒一次；不支持通知时仍有校验轮询，间隔跟随 EnergyGovernor 为 30–300 秒。锁屏/睡眠不读取；唤醒重新核实。多个窗口的 SessionMonitor 共享一个观察器，最后一个所有者退出后移除通知资源；正常退出永久停止新读取，并有界等待已取消工作。

启用和暂停只保存布尔设置。Bot 名称、Activity 标签、窗口树、临时行标识及导航结果均不落盘，也不进入现有 RecentSessionIndex、路由缓存、Bridge 日志或遥测。生产观察没有编码/持久化接口。

## 验证与剩余工作

合成数据位于 `Fixtures/mac-island-personal-agents.json`，显式设置 `MAC_ISLAND_FIXTURE_PATH` 后可以预览；测试/夹具在 SessionMonitor 和实际 AX 读取器两层拒绝真实客户端读取。产品门禁包含 `PersonalAgentObservationTests` 和 `PersonalAgentMonitorTests`，覆盖私有子树、同名活动、身份/状态缺失、版本变化、权限撤销、旧响应、退出、暂停/休眠和多所有者。

本轮依照用户要求，在开发完成后统一运行一次完整门禁。实际自动化结果、UI 核对和未运行真实场景另记录在 [验证记录](personal-agent-validation.md)。后台、最小化、多窗口真实观察、运行/审批状态和跨睡眠的完整工作时段/24 小时验收尚不能由合成数据证明。持续观察等级和具体任务导航保持未认证，Dot 来源继续由 #29 跟踪。

出现问题可先关闭单个观察项；这不会删除来源历史。代码回退使用审查后的 revert，安装回退使用原副本备份。
